# TA-C - Website, self-driving site and measurement

This chapter is part of the Track-A appendix: the marketing organism, fenced as engineering and method, never as science. It carries the public web presence for the SolutionWright Universal brand family and the first two phases of a planned self-instrumenting site. The honest position up front: what is shipped here is built software and operational discipline. It is not evidence about the UNI science, it does not demonstrate active inference, and a meaningful part of the measurement layer is deliberately switched OFF until an operator sets one environment variable. The strongest single fact in this chapter is also the most easily misread, so it is stated plainly: the site is built to measure itself, but it is not measuring anything yet, by design.

Everything below cites the claim ledger directly (rows TA19 through TA24, Section 4.3) and authors every shipped result alongside the negative or fence that travels with it.

## What shipped, with each result paired to its fence

**A full site, build-clean (TA19, Class E).** The public site is a Next.js 16 application, 26 routes plus an `/api/intake` endpoint, with `next build` and `tsc` both clean and a safety sweep that enforces zero em-dashes and zero "LEAP" in shipped copy. This is a Class-E claim: test-covered and build-covered, not a runtime capability observation. Class E means DONE in the sense of "the build is green and the sweep passes," not "a user did the thing." The falsifier is operable: `next build` or `tsc` fails on main, or the sweep finds an em-dash or the string "LEAP" in shipped copy.

**Three domains live on Vercel (TA20, Class A).** Three domains were cut over to Vercel with DNS verified live: `solutionwright.com` was flipped indexable in a Production-only environment for the press push, and `iamhitl.com` was cut over to the Evidence Explorer with the Printify store relocated to `store.iamhitl.com`. This is Class A, a live observation, not merely a passing test. Its falsifier is a live DNS or HTTP check showing a domain not resolving to Vercel or not serving the intended app, or indexability that is not Production-scoped. The travelling caution from the archive: production runs through a separate Vercel team reachable only via the dashboard, while the MCP token and CLI are bound to an older account that cannot see production. Drive production through the dashboard, not the CLI.

**Self-driving Phases 0 and 1, shipped (TA21, Class A for ingest / Class C for the storage gate) - and the load-bearing OFF fence.** On 2026-06-25 the first two phases of the self-driving site shipped to production: a storage-agnostic Postgres adapter (Neon as the hot store, the appliance as a sovereign async mirror) and a no-PII, salted-daily-id first-party measurement path that degrades to CANON on DNT or error. The Phase-0 storage gate is a Class-C dev-gate PASS: 2000 of 2000 writes with identical checksums. The sovereign ingest path was proven end-to-end from the open internet: a valid beacon returns 204 with the row inserted PII-stripped, a Do-Not-Track signal produces no insert, a bad origin returns 403, and 8 smoke routes return 200.

That is a genuine, observed result. It must always be cited next to its fence, because the fence is the whole point of this chapter: **measurement is OFF.** The live beacon no-ops until `NEXT_PUBLIC_INGEST_URL` is set in the Vercel environment and a redeploy fires. This is a deliberate degrade-to-CANON safety, not a defect: with no ingest URL the site serves a deterministic content rotation (CANON) and captures nothing. So the calibrated statement is: the measurement plumbing was built and proven able to capture, strip PII, and reject correctly under test, and it is currently capturing nothing in production by design (the parked owner action TA-P4). The falsifier for the shipped claim is sharp: the storage gate fails, measurement leaks PII or fails to degrade to CANON on DNT, or a smoke route returns non-200.

**The SEO/GEO program (TA22, Class A).** Shipped on SolutionWright: a cross-domain JSON-LD `@graph` with stable `@id`s, per-site `llms.txt` and `llms-full.txt`, a sitemap and robots welcoming AI crawlers, and a Node link-crawler. The brand-family wiring uses one canonical `@id` per real-world entity, identical on every page and domain, with `parentOrganization` and `founder` pointing to the same organization and Person `@id`, a `sameAs` ring across the sibling sites, and `Claim` rather than the retired `ClaimReview`. Class A: verifiable live. Falsifier: live JSON-LD `@id`s are not stable or identical across pages, the machine-facing files are missing on a shipped site, or retired schema types are used. The honest companion bound, recorded as a Track-A negative (TA-N7): AI search crawlers rarely fetch `llms.txt` and Google has said it will not support it. Ship it as a cheap, correct machine-facing gesture for agentic and IDE tools, never as a ranking lever.

**The press-readiness audit harness (TA23, method / Class E).** A reusable, four-phase parallel-agent audit: per-site SEO/GEO, a cross-domain JSON-LD entity-graph check, five personas (press-journalist, prospective-client, skeptical-scientist, answer-engine for GEO, and accessibility-mobile), and a GO / HOLD synthesis, producing a prioritized P0/P1/P2/polish scorecard. Its defining discipline is that it fetches the LIVE HTML via curl and never asserts from memory. This is a method claim, a reusable governance pattern, not a capability. Its falsifier (the violation): the audit asserts from memory rather than fetching live HTML, or skips a persona or a phase.

**The Reading Room, the evidence data-walk, and i18n (TA24, Class E).** The `/watch` "Reading Room" was rebuilt as an interactive all-ages curated library (mood and audience chips, multi-language, watch-later) over roughly 900 or more films. The evidence data-walk tool presents 44 graded primary-research findings with a three-way mode switch and, by deliberate design, makes NO recommendation: it shows the evidence and the trade-offs and lets the reader decide. Internationalization spans 822 keys across 10 languages on the UNI and Evidence Explorer surfaces. Class E. Falsifier: `/watch` does not render the curated library or its chips are non-functional, the data-walk emits a recommendation or its counts differ from 44 findings and 3 modes, or the live key and language counts differ from 822 and 10.

## The discipline that makes this Track-A, not science

Two patterns are worth naming because they are the reusable assets. First, no-PII first-party measurement: a `sendBeacon` on `visibilitychange`, validated against a taxonomy allowlist, PII stripped, stamped with a salted daily HMAC visitor id that creates no cross-day linkage and no tracking cookie, with DNT and GPC producing zero capture, absolutely. Second, deterministic global rotation: `floor(epochMs / windowMs) % count` gives every visitor the same content in a window with no server state, used both for the hero puzzles and for the CANON fallback. The self-driving design is a framing lens only; no such loop is demonstrated on these pages.

## Falsify this

Set `NEXT_PUBLIC_INGEST_URL` in the Vercel environment, redeploy, and send a beacon: if a valid event does not insert a PII-stripped row returning 204, or a Do-Not-Track signal does not produce zero capture, or a bad origin does not return 403, or the storage gate does not reproduce 2000 of 2000 writes with identical checksums, then the TA21 claim is falsified at the point where it matters most. Equally: run `next build` and `tsc` on main and run the safety sweep - any failure, em-dash, or "LEAP" in shipped copy falsifies TA19.
